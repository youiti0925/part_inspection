# 部品検査 社内サーバ版(PocketBase だけで動く版)の作り方 — 2026-10-29

## スイッチは1つ
- `npm run build:onprem`(= `vite build --mode onprem`)。`.env.onprem` の `VITE_ONPREM=1` が入り、出力は `dist-onprem/`。
- いつもの `npm run build` / `npm run deploy` は何も変わらない(行き先は Firebase のまま)。

## 社内版で変わる事
| 何 | 社内版 | 場所 |
|---|---|---|
| Firebase の起動(initializeApp・匿名ログイン・Firestore・Storage) | 呼ばない | src/App.jsx の Firebase の useEffect の先頭 |
| 保管庫 | 6領域すべて PocketBase(連絡・通知の宛先も) | src/onprem.js `ONPREM_PROVIDERS` / src/dataRoute.js |
| 写真・資料 | PocketBase の `blobs` へ上げる | src/data/pocketbaseBackend.js `uploadFile` |
| 通知(FCM) | 使わない。「社内版では通知を使いません」 | src/contact/ContactKit.jsx の先頭 |
| firebase-messaging-sw.js | 登録しない・出力からも外す | src/main.jsx / vite.config.js |
| 外の Worker(Drive・Gemini) | 空 = 「未設定」と出す | .env.onprem |

## 置き方
1. `npm run build:onprem`
2. `node scripts/deploy-onprem.mjs --to <社内サーバのフォルダ> --dry-run` で確かめてから `--dry-run` を外す
   (前の assets は消さない・onprem-config.json は上書きしない・index.html は最後)。
3. 写し先の index.html の横に `onprem-config.json` を置く(見本 `docs/onprem-config.example.json`)。
   端末用アカウントの合言葉は **ここにだけ** 書く(VITE_ に書くと JS に焼き込まれる)。

## まだ確かめていない事
- 本物の PocketBase での起動・読み書き(試したのは、行き先の無い PocketBase へ向けた時に Firebase へ1件も通信しない事まで)。
- 保存計画(commitVersion)は PocketBase のまとめ書き `/api/batch` を使う。サーバの設定で有効にする必要がある(無効なら書かずに理由を出す)。
- `blobs` のファイルを `<img>` で見るには、blobs の閲覧の決まり(viewRule)で端末が読める事が要る(未確認)。
- https・アプリとして入れる(SW)・サブパスで置く・共有の箱(4アプリ共通)をいつ移すか は清水さんの判断待ち。
