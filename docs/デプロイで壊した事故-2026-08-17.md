この文書は4つのアプリ（最終検査・製品検査・部品検査・司令塔③）に同じ物を置いてあります。

## 1. 何が起きたか

8/12 から画面を開いたままにしていた端末（Edge）で、**8/17 にアプリが起動しなくなりました。**

起動しないので、**その端末に貯まっていた 8/12 の作業（時間取り）が、送られないまま消えました。**

清水さんが最初に気づいたのは「8/12 に最終検査でした作業が、8/17 に見たらタッチアップエリアにあった」
「指図は 1001456630、1001580838」でした。
そのあと「**作業が〇じゃなくて、作業した時間取りデータが全部なくなってるね**」と訂正をもらいました。

**〇が消えたのではなく、作業時間が消えていました。**（＝約束の P28）
この文書は、**その時間を送れなくした側**の話です。

## 2. なぜ起きたか（実測した事実）

本番のアドレスを1つずつ叩いて確かめました。

| 部品の名前 | 返ってきた物 | 意味 |
|---|---|---|
| `/assets/index-D4LMK6Kl.js` | **200 text/html** | 消えている。HTML が返ってくる |
| `/assets/index-Dp0LoHux.js` | **200 text/html** | 消えている |
| `/assets/index-MOelDncI.js` | **200 text/html** | 消えている。8/12 の端末はこれを読みに行った |
| `/assets/index-xjtw4ujW.js` | 200 text/javascript | いまの物だけ本物 |

**2つのことが重なりました。**

### ① 出すたびに、前の部品を踏み潰していた

`firebase deploy` は、手元の `dist` の中身で本番を**丸ごと置き換えます。**
アプリの部品は、中身が変わると名前も変わります（`index-D4LMK6Kl.js` → `index-xjtw4ujW.js`）。
なので**新しく出すたびに、前の名前の部品は本番から消えていました。**

**5日で19回出しました。19回ぶん、踏み潰しました。**

### ② 消えた物を頼まれた時、HTML を返していた

`firebase.json` の設定が `"source": "**"`（＝**何を頼まれても** index.html を返す）でした。
だから、消えた部品を頼まれた時も **「無い」と言わずに、アプリの表紙(HTML)を返して**いました。

### ③ その結果

古い画面を開いたままの端末は、**自分が掴んでいる古い名前**の部品を取りに来ます。

```
古い端末:「index-MOelDncI.js をください」
本番    :「はい（中身は HTML）」
ブラウザ:「これは JavaScript じゃない。構文エラー」→ アプリが起動しない
```

起動しないアプリは、貯めていた作業を送れません。**そのまま消えました。**

## 4. これから何が変わるか

### ① 出す口を1つにしました

```
npm run deploy
```

この中で、必ず この順に通ります。飛ばせません。

| 順 | やる事 | 落ちたら |
|---|---|---|
| ① | 📋 約束の見張り（`npm run check`） | 止まる |
| ② | 🛡 出す前の見張り（`verify-deploy-safety --pre`） | 止まる |
| ③ | 🏗 ビルド → 🧳 **古い部品の持ち越し**（`keep-old-assets`） | 止まる |
| ④ | 🚀 出す | 止まる |
| ⑤ | 🔬 **本番で実測**して照合（`--after`） | 出た事を報告しない |
| ⑥ | 📒 出した物を台帳に控える | — |

出さずに手前まで確かめるだけなら `npm run deploy:dry`。

### ② 古い部品を捨てなくなりました

`scripts/keep-old-assets.mjs` が、出すたびに部品を置き場（`.hosting-attic`）に貯めて、
**次に出す時に一緒に本番へ戻します。**（既定 30日ぶん）

「直近5世代」ではなく「**直近30日**」で残します。
今回の事故は「5日間 開きっぱなし」で起きて、その5日で19回出しているので、
5世代では 1.3日しか残らず**今回の事故は防げなかった**からです。守るのは回数ではなく**日数**です。

### ③ 出す前に、機械が名指しで止めます

```
node scripts/verify-deploy-safety.mjs
```

見る所（全部、出どころつきで出ます）:

| | 見る事 |
|---|---|
| D0 | **見張りの読み方が、本物の判定器と同じ答えを出すか**（毎回突き合わせる） |
| D1 | 出し方が1つの口か（見張りを通さない裏口が無いか） |
| D2 | 無い部品に HTML を返す設定になっていないか |
| D2b | 直しすぎて、画面のリンクまで 404 にしていないか |
| D3 | **次に出す dist に、いま生きている部品が全部入っているか**（入っていない物を名指し） |
| D4 | **無い物を頼んだら本当に 404 が返るか（本番で実測）** |
| D5 | 台帳が本番に追いついているか（口を通さずに出していないか） |
| D7 | 出しすぎていないか（今日 何回 / 7日で 何回） |

⚠**「確かめられなかった」は合格にしません。** 分からない物は赤で出します。
⚠D4 には**対照**を置いてあります。実在する部品が 200 で返る事を先に確かめてから、
無い物を頼みます。対照が取れない時は「合格」と言わず「**この試験は信用しない**」と出します。

### ④ 見張り自身も試験します

```
node scripts/selftest-deploy-safety.mjs
```

作り物の設定を **15個**作って、**わざと壊した物で本当に落ちるか**を確かめます。
「ちゃんとした形」の見本も置いてあります（**誤検出したら赤くなる**ので、いつも赤い見張りにならない）。

この試験を作った事で、実際に見張りの穴が**4つ**見つかりました。**作った当日に、自分の見張りが4回嘘をつきました。**

- 出す前の `dist` を対照に使っていた（`dist` には**まだ出していない次の版**が入っているので、本番に無くて当たり前。毎回「分からない」と言う嘘の警告になっていた）
- `deploy.bat` の裏口を見落としていた（`set FIREBASE=npx firebase` と置いてから `%FIREBASE% deploy` と書いてあるので、`firebase deploy` という字面を探しても当たらない）
- 台帳が空の時に「大丈夫」と読める出方をしていた
- ビルド前の `dist` を見て「消える」と赤を出していた（持ち越しの仕掛けで戻る物まで赤にすると**毎回赤**になり、そのうち誰も見なくなる）

さらに、**見張りの読み方自体が正しいか**も毎回突き合わせます（D0）。
設定の書き方を読む所は、最終検査では**本物の判定器**（`minimatch`＝`superstatic` が使っている物）で測り、
それが無いアプリでは自前の読みを使うので、**両方が同じ答えを出す事**を8通りの道で毎回確かめます。

## 6. 次に同じ事を起こさない為に、まだ足りない事

見張りは「**部品が消える事**」を止めます。でも、それだけでは足りません。

1. **アプリ側**が、部品を読めなかった時に**黙って死なない**事。
   読み込みに失敗したら「新しい版が出ています」と出して読み直す。（`src` 側の仕事）
2. **貯まった作業が、アプリが起動しなくても残る**事。
   いまは起動しないと送れません。ここが**損害になった本当の場所**です。（P28）
3. **出す回数を減らす**事。1日4回出す必要は、たぶんありません。

⚠ 1と2は `src` の担当です。この文書では**まだ手を付けていません**（範囲を勝手に広げないため）。
**やらない判断は清水さんの物**なので、ここに書いて残します。
