# 社内版(部品検査): サーバの名前・置き場所の変え方

> 🏢 2026-10-30 夜: 既定の置き方は**アプリごとに口(ポート)を分ける**形に変わりました(製品 `https://kensa.local:8441/`・最終 `:8442/`・部品 `:8443/`・③ `:8444/`。どの口でも `/api/` は同じ PocketBase)。`onprem-config.json` の `url` は**空 = 画面と同じ口**にし、住所は `appUrls` だけで変えます。入口と手順の正本は最終の worktree の `tools/onprem/README_社内サーバー手順.md` §4。下の階層(`/product/` など)に置く形も引き続き使えます。

社内版(`npm run build:onprem` で作る `dist-onprem`)は、サーバの名前や置き場所を **ビルドし直さずに** 変えられます。
変える所は **1つのファイルだけ** です。

## 変える所

`dist-onprem` を置いたフォルダ(`index.html` と同じ場所)の **`onprem-config.json`**。

最初は `onprem-config.sample.json`(ビルドの時に一緒に出る見本)を写して名前を変えて使います。

```json
{
  "url": "",
  "authCollection": "device_users",
  "appUrls": {
    "product-inspection-v1": "https://kensa.local:8441/",
    "final-inspection-v1": "https://kensa.local:8442/",
    "parts-inspection-v1": "https://kensa.local:8443/",
    "overview-app-v1": "https://kensa.local:8444/"
  }
}
```

| 鍵 | 意味 |
|---|---|
| `url` | データの置き場(PocketBase)の入口。https の入口の一番上 |
| `appUrls` | 4アプリの置き場所(③が他のアプリへのリンクに使う。部品は読むだけ) |
| `authCollection` | 端末用アカウントの置き場(既定 `device_users`) |

- 今の `https://kensa.local` は **仮の名前** です。社内サーバの名前が決まったら、ここを書き換えるだけで動きます。
- 書き換えた後は、各端末で画面を開き直すと新しい値が読まれます(このファイルは毎回サーバから読み直します)。
- 🔒 端末用アカウントの `email` / `password` はこのファイルに書きません(2026-10-30 から。入口がいつも外します)。
  各 PC で最初に開いた時のログインの画面で1回だけ入れます(「ファイルから読む」で `device-login.json` を読ませてもよい)。
- ⚠ 写し直し(`node scripts/deploy-onprem.mjs --to …`)は、写し先の `onprem-config.json` を上書きしません。

## 置き場所

アプリはサーバの一番上(`/`)でも、下の階層(例 `/parts/`)でも動きます(社内版は全部の読み先が `index.html` からの相対です)。
下の階層に置く時は、URL の最後に `/` を付けて開きます(例 `https://kensa.local:8443/`)。
