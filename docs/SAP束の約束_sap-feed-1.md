# SAP 束の約束 `sap-feed/1`(案・段1・11-24)

元: docs/設計_SAP生データ取込と加工_1123.md の C-3(束の形)・A-5(汚れ・癖 D1〜D17)・C-2(検査)。**設計の案をそのまま表にした物**で、設計に無い決め事は「要確認」と書いた(推測で埋めていない)。
束 = 段2(絞る)が作り、段4(読む)が読む JSON 1 個。毎回まるごと作り直して上書き・同じ入力なら同じ束(設計 C-4)。

## 1. 全体(トップの項目)

| 項目 | 型 | 必須 | 中身 | 根拠 |
|---|---|:-:|---|---|
| `schema` | 文字 | ○ | 固定 `"sap-feed/1"`。知らない版は読み手が止まる | C-2 段4 |
| `baseDate` | 文字 `YYYY-MM-DD` | ○ | 基準日(RPA の「今日」=説明シートの『今日（計算の基準日）』) | C-3・D16 |
| `generatedAt` | 文字 ISO 8601(`+09:00` 付き) | ○ | 作成日時(説明シートの『作成』)。`baseDate` と別に持つ(1 日ずれる事がある=D16) | C-3・D16 |
| `source` | 物 | ○ | `fileName` 文字・`sheetRows` 物(シート名 → 行数) | C-3 |
| `checks` | 物 | ○ | 段1・段2 の検査①〜⑫ の結果(`id`・`ok` 真偽・`count` 数・`note` 文字)と、捨てた行の理由別の件数 | C-2 |
| `wcMap` | 物 | ○ | 作業区(文字) → 名前(文字) | C-3・D10 |
| `orders` | 配列 | ○ | 指図の行(2 章) | C-3 |
| `ops` | 配列 | ○ | 工程の行(3 章) | C-3 |

## 2. `orders` の 1 行

| 項目 | 型 | 必須 | 欠けた時 | 癖・規則 |
|---|---|:-:|---|---|
| `order` | 文字 | ○ | 行ごと捨てて理由付きで数える | D1: 数に直さない・先頭の 0 を落とさない・英字始まり・12 文字あり |
| `item` | 文字 | - | `null` | 空は 1,719/21,491(見本) |
| `itemText` | 文字 | - | `null` | D15: `,`・全角・空白が入る。型式の比べ方は今ある `normalizeModel` に揃える(束では加工しない) |
| `type` | 文字 | ○ | - | ZHK1 など |
| `qty` | 整数 | ○ | - | |
| `baseStart` / `baseEnd` | 文字 `YYYY-MM-DD` | ○ | - | D4: 日だけ・時刻を作らない・D17 先は薄い |
| `statusTokens` | 文字の配列 | ○ | - | システム Status を空白で割った記号(REL・CNF …)。終わりの印の判定は段2 が持つ(`DONE`: TECO・CMPL・DLV・CLSD・DLT・LKD) |
| `issueDate` | 文字 `YYYY-MM-DD` | - | `null`(=「出庫日なし」と画面に出す) | D14: 出庫日が分かるのは一部。元は「組立指図」シート(見出しは設計書に無い=要確認) |

入れる指図 = **未完了の工程がある指図だけ**(終わった指図 TECO 等は外す=D9。外した件数は `checks` に出す)。

## 3. `ops` の 1 行

| 項目 | 型 | 必須 | 欠けた時 | 癖・規則 |
|---|---|:-:|---|---|
| `order` | 文字 | ○ | - | `orders` に全部ある事(検査④) |
| `act` | 文字 4 桁 | ○ | - | D2: 数にしない(`0010`)。並びは文字で |
| `wc` | 文字 | ○ | 作業区が空の行は「読めない行」に数えて束に入れない | D10。`B05` の様な英字つきもある |
| `qty` | 整数 | ○ | - | |
| `std1` `std2` `std3` | 数 または `null` | - | `null`=時間は不明 | D5: 全部 0 の工程が 45%・仮の時間を入れない。単位が H でない/空の行(D6)は `null` にして `checks` に件数 |
| `done` | 真偽 | ○ | - | D3: 済/未の 2 つだけ(作業中は作らない)。済 = 実績終了日がある |
| `actualEnd` | 文字 `YYYY-MM-DD` | - | `null`(未) | D3: 実績の開始と終了は同じ日。D8: 土日もそのまま |
| `earlyStart` / `earlyEnd` | 文字 `YYYY-MM-DD` | ○ | - | |
| `suspectOrder` | 真偽 | - | 既定 偽 | D7: 前の工程が未で後ろが済=「入力もれらしい」の印・順番は直さない |

工程の鍵は **`order` + `act`**(重複 0 が検査③)。確認番号は入れない。

## 4. `history`

| 項目 | 型 | 必須 | 中身 |
|---|---|:-:|---|
| `weekly` | 配列 | ○ | `wc`・`week`(`YYYY-MM-DD`=週の月曜)・`hours` 数・`count` 整数 |

## 5. 入れない物(束の中に欄そのものを作らない・検査⑪)

客先名・仕入先名・金額(単価など)・購買発注・在庫の値・MRP 管理者・製造責任者・確認番号。`checks` に **これらの欄名が束の中に 0** である事を書く。

## 6. 版の上げ方

- 欄を**足す**(読み手が知らなくても動く)= `sap-feed/1` のまま。読み手は知らない欄を無視する。
- 欄を**消す・名前や型を変える・意味を変える**(例: 日付の書き方・`done` の意味)= `sap-feed/2` に上げる。読み手は知らない版で止まって画面に理由を出す(間違った束を黙って読まない)。
- 上げる時は ①この文書に新しい版の節を足す(古い版の節は残す) ②合成 Excel の道具と見出し一覧(`scripts/sap_synth/headers_spec.json`)は元の Excel の形の約束なので、束の版とは別に扱う ③読み手は直前の版を 1 つ前まで読めるようにするかをその時に決める(要確認)。

## 7. 要確認(設計書に答えが無い)

- 上の `weekly`・`usualDays` の欄名と週の数え方(過去 12 週・設計 A-2「実績_週」の見出しが書かれていない)。
- `checks` の `id` の付け方(① 〜 ⑫ は設計の通し番号を使う案)。
- `wcMap` の名前の元(「作業区」シートの見出しが書かれていない)。
- 項目名(`order`・`act` …)は 案 です。設計 C-3 は日本語の見出し(指図・活動 …)で書かれており、JSON のキー名は未決。
- 置き場(Firebase・社内・端末)は設計 F-2 の 1 の答え待ち。1 個 700KB 以下に割る時の分け方も未決(C-6)。
