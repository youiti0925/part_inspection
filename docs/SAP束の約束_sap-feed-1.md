# SAP 束の約束 `sap-feed/1`(案・段1・11-24)

元: docs/設計_SAP生データ取込と加工_1123.md の C-3(束の形)・A-5(汚れ・癖 D1〜D17)・C-2(検査)。**設計の案をそのまま表にした物**で、設計に無い決め事は「要確認」と書いた(推測で埋めていない)。
束 = 段2(絞る)が作り、段4(読む)が読む JSON 1 個。毎回まるごと作り直して上書き・同じ入力なら同じ束(設計 C-4)。

## 4. `history`

## 5. 入れない物(束の中に欄そのものを作らない・検査⑪)

客先名・仕入先名・金額(単価など)・購買発注・在庫の値・MRP 管理者・製造責任者・確認番号。`checks` に **これらの欄名が束の中に 0** である事を書く。

## 6. 版の上げ方

- 欄を**足す**(読み手が知らなくても動く)= `sap-feed/1` のまま。読み手は知らない欄を無視する。
- 欄を**消す・名前や型を変える・意味を変える**(例: 日付の書き方・`done` の意味)= `sap-feed/2` に上げる。読み手は知らない版で止まって画面に理由を出す(間違った束を黙って読まない)。
- 上げる時は ①この文書に新しい版の節を足す(古い版の節は残す) ②合成 Excel の道具と見出し一覧(`scripts/sap_synth/headers_spec.json`)は元の Excel の形の約束なので、束の版とは別に扱う ③読み手は直前の版を 1 つ前まで読めるようにするかをその時に決める(要確認)。

## 7. 決めた事(段2・11-24)と、まだ要確認

決めた(束を作る関数 `scripts/sap_feed/feed.py` に入っている・試験つき):
- 項目名は 2〜4 章の英名(`order`・`act`・`wc`・`std1` …)で確定(`sap-feed/1`)。理由: 設計 C-3 の日本語見出しは SAP 側の名前で、JSON のキーは別に持つ方が見出しが変わっても読み手が壊れない。
- 検査の `id` は設計の通し番号(①〜⑫)に、型の検査 `P1`(日付が文字・指図が数値セル・空など)を足した。理由: 設計 C-2 の ① は「見出しがあるか」だけで、型が違う物を止める検査が無かった。
- ⑧⑨⑩(件数・時間・作業区ごとの差)は、RPA の計算シート「工程_未完了」が合成では空なので、`.truth.json` の答え+別の数え方(辞書と Counter だけで数える別の経路)で代用する。`checks.notes` と各検査の `note` に代用した事を書く。本物で「工程_未完了」に行があれば行数も比べる(時間と作業区ごとは見出し不明のため行数だけ)。
- ⑨の時間は「単位が H の 標準値1+標準値2×数量」。単位が空・H でなく外した分と、作業区が空で外した行の分を足し戻して、参照(別の数え方・truth)と比べる(外した分は `info` に件数が出る)。
- ⑦ 実績の一番新しい日が基準日の 7 日以内。実績が 1 件も無い時も赤。⑫ の上限は 1,000,000 バイト(見本で約 850KB・案=要確認)。
- ② 行数の比べは、前回の記録(`sap-feed-record.json` の `rowCounts`)を渡した時だけ。初回は省略と書く。
- 束に入れる工程 = 終わっていない指図の工程すべて(済の工程も含む=前の工程の実績に使う)。作業区が空の行だけ「読めない行」として外し、理由別の件数を `dropped` に出す。
- 標準値が 3 つとも 0 の工程は `std1〜3` を全部 `null`(時間は不明・D5)。単位が H でない・空の値は `null`(D6)。
- 指図・活動・作業区が数値セルで入っている Excel は `P1` で止める(先頭の 0 が落ちている恐れがあり、元に戻せないため)。

まだ要確認(設計書に答えが無い):
- 「作業区」「作業区MT」「実績_週」「組立指図」「不足部品」「工程_未完了」シートの見出し(合成も本物の見出しが無いので読んでいない)。`wcMap`・`usualDays`・`issueDate` が空なのはこのため。
- `history.weekly` の「過去 12 週」の数え方が RPA の「実績_週」と同じか。
- 置き場(Firebase・社内・端末)は設計 F-2 の 1 の答え待ち。1 個 700KB 以下に割る時の分け方も未決(C-6)。
