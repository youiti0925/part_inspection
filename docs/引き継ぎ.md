## 4. 出す(本番／プレビュー／前の版へ戻す)

### 4-1. GitHub の上から(Claude の端末が要らない道) — `.github/workflows/deploy.yml`

GitHub → Actions → **Deploy** → Run workflow:

| 入力 | 意味 |
|---|---|
| `ref` | 出す版。ふだん `master`。**前の版へ戻す時は そのコミット番号**(7桁) |
| `preview` | `true`(既定) = プレビューの住所へ(本番は変えない・7日で消える)／`false` = 本番へ |
| `reason` | 出す理由。台帳(`scripts/deploy-ledger.json`)と実行の記録に残る |

通る道は手元と同じ: `npm ci → npm test(赤なら出さない) → [preview: firebase hosting:channel:deploy] / [本番: node scripts/deploy.mjs --skip-check --frequency-ok = build → 古い部品の持ち越し(keep-old-assets) → firebase deploy → 台帳 → 本番で照合]` → 台帳を `ref` の枝へ commit/push。
プレビューの住所は 実行の Summary に出る。**プレビューも本番の Firestore に繋がる**ので 見るだけ。

**1回だけの準備(清水さんの端末で・鍵をチャットや Git に貼らない為の正式な経路)**

```bash
cd C:\Users\anrw3\product-inspection-app     # 4リポジトリそれぞれで
npx firebase login                            # 済んでいれば飛ばす
npx firebase init hosting:github
#   → GitHub にブラウザで許可 → リポジトリ名 youiti0925/product-inspection → 質問は全部 No(ビルド・PR・merge の自動デプロイは要らない)
#   これが (a) サービスアカウント github-action-…@inspection-time-c4fd3.iam.gserviceaccount.com を作り
#          (b) その鍵を GitHub Secrets の FIREBASE_SERVICE_ACCOUNT_INSPECTION_TIME_C4FD3 に置く
#   生成された .github/workflows/firebase-hosting-*.yml は消す(出す口は deploy.yml の1本)
```

- サービスアカウントの役割は Hosting 管理まで。**Firestore は書けない**(Google Cloud → IAM で確かめられる)。鍵を漏らしたら IAM でその鍵を消せば無効になる。
- deploy.yml は 鍵が無ければ **何もせずに止まる**(最初の段で確かめる)。
- 4リポジトリ全部に同じ deploy.yml を置いた。secret は リポジトリごとに置く(同じサービスアカウントの鍵を4回置いても良い)。
- 本番へ出す時に承認を挟みたければ GitHub → Settings → Environments → `production` に Required reviewers を付ける(deploy.yml は `production`/`preview` の environment を使っている)。

### 4-3. 前の版へ戻す

1. `git log --oneline` で戻す版のコミット番号を決める(台帳 `scripts/deploy-ledger.json` に 出した日時と束の名前が並んでいる)。
2. Deploy を `ref=<その番号>` `preview=false` で押す。古い部品は持ち越されるので、開きっぱなしの端末も壊れない(2026-08-17 の事故の対策がそのまま効く)。
3. 戻した後に master も戻すなら `git revert`(`reset --hard` はしない)。
