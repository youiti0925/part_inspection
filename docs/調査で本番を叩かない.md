# 🚨 調査で本番を叩かない ── Claude（私）の決まり

> この紙は **私（Claude）が守る決まり**です。人に頼む物ではありません。
> 4アプリ（最終検査 / 製品検査 / 部品検査 / 司令塔③）に同じ物を置いてあります。

---

## 1. 何をしたか（事実だけ）

**2026-08-16 〜 08-17、私は本番のアプリをブラウザで何十回も開いて、スマホ表示の寸法を測りました。**

- 本番のアプリは、**1回開くと数百件を読みます**。
  実測の内訳（`node scripts/verify-read-budget.mjs`）:

  | アプリ | 1回開くと |
  |---|---|
  | 最終検査 | **1,242件** |
  | 製品検査 | **1,511件** |
  | 司令塔③ | 開いた時 978件 ＋ 自動更新1回ごとに 709件 |

- 1日に読める上限は **50,000件**。**4アプリで1つ**を分け合っています。
- つまり最終検査を N 回開けば **1,242 × N 件**。
  **N=10 で 12,420件（上限の25%）／ N=30 で 37,260件（上限の75%）。**

そして 2026-08-17 の 14:36〜15:59、本番の読み取りが全部エラー(429)で止まりました。

## 2. ⚠ 決めつけない（ここが大事）

**私の調査が原因だと決めつけません。** 理由:

- **N（私が何回開いたか）を数えていません。** 記録を残していませんでした。
- そもそも見積りでは、**③司令塔のタブ1枚だけで1日 77,550件**＝
  **上限の1.5倍**を使います。**私が1回も開かなくても枠は超えます。**
- 1日の合計見積りは **199,688件＝上限の399%**。

> つまり **私の調査は「上乗せ」であって、主因とは言えません。**
> しかし **上乗せしてよい余裕はどこにもありませんでした。**
> 「主因ではない」は「やってよかった」ではありません。

⚠ 2026-08-17 に私は「Edgeが壊れた」と言い、相関を因果と決めつけ、
原因が分からないまま「対策」と言いました。**同じ事をここでもしません。**

## 3. これからの決まり

### 決まり① 🚫 本番のアプリを **ブラウザで開かない**

見た目・寸法・動きを測るのは、この順で:

1. **開発サーバ**（`npm run dev`。私の番号は **5290以降**。終わったら止める）
2. **Firebase エミュレータ**（`scripts/load-backup-to-emulator.mjs` で中身を入れてから）
3. それでも足りない時だけ、下の決まり②へ

> 本番を開いて測ってよいのは **人（清水さん）が「本番で見て」と言った時だけ**です。
> その時も**開く前に回数を宣言し、開いた回数を報告に書きます。**

### 決まり② 本番に触ってよいのは **curl で静的ファイルだけ・1〜2回まで**

```bash
curl -sI https://inspection-time-c4fd3.web.app/index.html
```

- **Hosting（index.html / assets/）はデータの読み取り枠を使いません。** これは安全です。
  （`scripts/verify-deploy-safety.mjs` と `scripts/keep-old-assets.mjs` はここだけを見ています）
- 🚫 **ブラウザで開くのは別物です。** ブラウザで開くとアプリが動き出し、
  **数百件のデータ読み取りが走ります。** curl は動きません。

### 決まり③ 測る前に「何件読むか」を先に出す

```bash
node scripts/verify-read-budget.mjs --json
```

**「これから何件読むか」を数字で言えないなら、実行しません。**

### 決まり④ 本番のデータを読む道具は、回数と件数を必ず記録する

| 道具 | 何を読むか | 決まり |
|---|---|---|
| `scripts/backup-daily.mjs` | 本番の全コレクション | 1日1回まで。読んだ件数は manifest.json に残る |
| `scripts/report-firebase-usage.mjs` | 使用量 | 読み取り枠は使わない |

`backup-daily.mjs` は **1回で全件（2026-08-11 実測 2,343件）** を読みます。
**枠が苦しい日は走らせない。**

### 決まり⑤ 🚫 本番のデータへ **書かない**

調査で書き込む事はありません。書きたくなったらエミュレータへ。

### 決まり⑥ 枠が切れた日は、本番を**一切**触らない

読めない日に開き直すと、**枠が戻る時刻（日本時間 16時ごろ・冬は17時ごろ）が来ても
すぐまた使い切ります。** その日は本番を見ずに、コードと実測ファイルだけで調べます。

### 決まり⑦ 道具に本番URLを直書きしない

- 既定は **localhost**、本番は環境変数で明示的に渡させる。
- ⚠ **いま本番URLを直書きしている道具**（最終検査）:

  | 道具 | 中身 |
  |---|---|
  | `scripts/verify-skip-saving.mjs` | `p.goto(process.env.BASE \|\| 'https://inspection-time-c4fd3.web.app/')` + 14秒待つ |
  | `scripts/verify-skip-unit.mjs` | `p.goto('https://inspection-time-c4fd3.web.app/')` + 14秒待つ（**環境変数でも逃げられない**） |

  **14秒待つ = 6秒で始まる lot_images(941件)まで全部読み終える** ＝ 1回で約1,242件。
  → **この2本は走らせない。** 直すなら既定を localhost にして、本番は `BASE=` で明示。

  ✅ `scripts/verify-mobile.mjs` は既定が `http://localhost:5310` で正しい形です。

## 4. 破っていないかの確かめ方

| 確かめる事 | やり方 |

> ⚠ **見積りと実測が食い違ったら、実測を信じます。**
